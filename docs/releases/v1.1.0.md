# v1.1.0 — HP ProLiant ML10 Gen9 Graphics / Display Fix

The first full, documented release. It fixes the **black screen / “no signal”**
on the HP **ProLiant ML10 Gen9** (Intel **HD Graphics P530**, Skylake) when a
monitor is connected through the motherboard’s DisplayPort via a passive
**DP → DVI → HDMI** adapter.

**Root cause, in one line:** the passive adapter hides the monitor’s **EDID**
(the driver’s GMBUS read fails), so the output is never enabled. `nomodeset`
“works” only by abandoning the GPU and pinning you to a firmware 1024×768
framebuffer with no acceleration.

---

## Highlights

- **Full root-cause analysis** — `nomodeset` / `video_firmware_drivers_only()`,
  the EDID/GMBUS bit-bang fallback, the dual-name DP++ port trap (`DP-1` vs
  `HDMI-A-1` are the *same* physical port), and Skylake power features.
- **Linux toolkit** (`i915-display-fix.sh`) — `status`, `detect`, `apply`,
  `discover`, `revert`; supports **GRUB** (Ubuntu/Debian/Mint, Fedora/RHEL/Arch/
  openSUSE) **and systemd-boot**. Non-destructive, timestamped backups, and a
  guaranteed `nomodeset` recovery entry.
- **Windows & Windows Server** — `Get-GraphicsInfo.ps1`,
  `Set-DisplayResolution.ps1`, `Install-IntelGraphicsDriver.ps1`,
  `Fix-Display.bat`, and a native **`DisplayFix.exe`** (source included).
- **FreeBSD** — `i915-freebsd.sh` (`i915kms`).
- **Documentation** — a 52-page PDF plus per-distro, troubleshooting,
  verification, hardware/adapter and FAQ guides.
- **Real screenshots** rendered from the reference machine’s actual output.

## The fix (Linux, in one line)

```
# remove nomodeset; add to the kernel command line:
i915.enable_dc=0 i915.enable_psr=0 i915.enable_fbc=0 i915.enable_dp_mst=0 \
i915.disable_power_well=0 video=HDMI-A-1:1366x768@60e
```

Replace `HDMI-A-1` with your connector and `1366x768` with your monitor’s native
mode. Keep the trailing `e`. **Never** force both `DP-1` and `HDMI-A-1`.

Or just:

```bash
cd scripts/linux
./i915-display-fix.sh detect
sudo ./i915-display-fix.sh apply
sudo reboot
```
